# 栖梧7班补充安全检查（2026-10-28）

结论：仍存在可利用的问题。按影响分为 3 项高优先级问题和 4 项中优先级问题。以下不是对事故责任人或历史攻击方式的认定。

## 检查范围与证据边界

- 审阅当前工作区 `qiwu7_server.py`、`index.html`、账户生成脚本、部署说明和现有测试。工作区原本有未提交的安全升级修改；本次没有修改这些业务文件。
- 使用现有测试的临时账户、合成数据和临时私有目录，启动独立的 localhost 服务复现，结束后删除临时状态。没有使用真实学生账户，也没有向生产服务提交数据。
- 对部署说明中的生产地址仅请求 `/api/ping`：HTTP 返回 200、`securityVersion=2`；同端口 HTTPS 握手报 `WRONG_VERSION_NUMBER`。这证明该入口仍提供明文 HTTP，不代表没有其他 HTTPS 入口。
- 没有取得线上服务代码摘要。因此下述业务漏洞是在本地当前代码上确认；线上版本号相同不足以证明部署代码逐字一致。
- 复现脚本：[reproduce.py](./reproduce.py)；机器可读结果：[evidence.json](./evidence.json)。脚本中的断言确认的是漏洞仍能触发，不能视为安全测试通过。

## 高优先级

### 1. 学生可读取他人的私密反馈、加分申请及完整成绩数据

位置：`qiwu7_server.py:208–211`、`:235–236`；`index.html:386` 的 `EMBEDDED_EXAMS` 数据。

`/api/sync` 向所有已完成改密的登录角色发送完整 master/shared；登录后的 HTML 初始化数据同样全量发送。学生页面隐藏“反馈总池”等入口，并没有限制网络返回的数据。HTML 中还内置整班历史考试数据，单纯过滤 API 不能解决这条泄露路径。

已复现：普通学生请求同步接口返回 200，能看到其他学生反馈标记、其他学生加分申请和考试数据；其首页 HTML 也包含他人反馈。这与页面“只有班主任能看到”的承诺不符。

修复：建立统一的按角色、按本人过滤的读取视图，同时用于 API 和 HTML 初始化；从通用 HTML 删除真实成绩数据。公开排名只提供所需的公开字段。调整全量同步协议，使客户端不会因看不到私密字段而覆盖、误删服务器数据。

### 2. 公用一体机会话可改写教师专属共享数据

位置：`qiwu7_server.py:104–120`、`:121–134`；`index.html:676–678`。

`priv` 同时包含 teacher 和 classroom，两种角色对 shared 数组都采用不受学生校验约束的整表替换。虽然 classroom 不能修改 master，但可以修改奖品、兑换状态、反馈、加分申请、积分及其删除标记。

已复现：使用 teacher 凭据取得 classroom 会话后，提交清空反馈、将奖品成本改成负数、将待审申请改成 approved，服务器返回 200 且状态持久化。修改审核字段不等同于证明对应积分已自动增加；直接改写积分记录则另有同一授权缺口。

利用前提：能操作老师已登录的一体机，或已持有 classroom 会话。无需获得教师端会话或修改前端角色。该会话有效期为 12 小时；前端 `roomScoreAuth()` 对 classroom 会话持续返回授权状态，不能提供独立的班干身份边界。

修复：classroom 使用独立的最小权限表，默认仅允许公开读取。确需登记积分时，应由具体班干进行短期服务端授权；奖品管理、审批、反馈读取及删除等留给教师。操作者署名由服务器生成。

### 3. 生产入口仍为明文 HTTP

位置：部署说明、`qiwu7_server.py:24–25`、`:323–325`、`:345`。

生产 HTTP 健康接口可访问，同端口 HTTPS 握手失败；代码直接提供 HTTP，Secure Cookie 默认关闭。若师生通过该 HTTP 入口登录，具备链路窃听或中间人条件的攻击者可获取密码、会话或篡改页面，绕过应用层权限防护。校园网本身不能替代传输加密。本次未拦截任何人的流量。

修复：部署受信任证书的 HTTPS 入口，启用 Secure Cookie；从学生网络关闭直连明文后端，仅允许反向代理访问。确认 HTTP 已无法承载登录后，撤销旧会话，并更换曾在明文入口使用的密码。

## 中优先级

### 4. 课代表可写入持久异常数据，导致积分页报错或插入 HTML

位置：`qiwu7_server.py:77–84`、`:113–119`；`index.html:2126–2130`、`:2147`、`:2163`、`:2515–2516`。

积分校验没有约束 batchId/sub/记录 ID 的安全格式和类型。前端使用普通对象按 batchId 分组，且把 batchId 和 ID 直接拼入 HTML 属性。

已复现：课代表提交合法类别和分值、但带异常 batchId 的记录，服务器返回 200。执行真实 `viewScoreTeacherOrClubUI()` 渲染函数时发生 TypeError；另一条带无害 `<b>` 标记的 batchId 被原样拼入输出 HTML。异常记录留在服务器，重新刷新不能消除它，受影响的积分视图仍会报错。

本次证据为服务器写入和 Node VM 中的实际渲染函数输出，未用真实浏览器验证最终 DOM。现有 nonce CSP 会阻止常见内联脚本；**未证明可执行 JavaScript 或接管教师会话**，不能把 HTML 注入直接称作已证实的 XSS 接管。

修复：各记录使用严格字段白名单、类型和长度约束；ID/batchId 使用受限字符格式；分组改用 Map；所有属性值正确转义或使用 DOM API 设置。渲染层还应能隔离已有异常记录，避免整页失败。

### 5. 积分缺少业务去重和历史日期约束

位置：`qiwu7_server.py:79–84`；`index.html:1554–1559`。

已复现：课代表为相同学生、相同作业、相同批次提交 3 个不同 ID 的记录，全部接受；指定任意历史 weekKey/date 也原样持久化。服务器只重写 ts/timeStr，而实际周分按提交的 weekKey 累加，因此改写服务器时间不能保证积分归属日期可信。

业务上确实发生的多次作业登记可以合法重复；漏洞在于服务器无法识别同一业务事件的重放，也没有区分当前登记和教师历史补录。

修复：为作业/回答事件建立业务事件 ID 和服务端幂等约束，限制可登记的时间范围；历史补录单列教师权限。累计限额应由老师确定，不能任意硬编码影响正常课堂。

### 6. 学习时长可直接伪造并无限叠加

位置：`qiwu7_server.py:90–91`；`index.html:2858–2863`。

已复现：普通学生一次提交两条同日 1440 分钟记录，即使 startTs/endTs 只有 1 毫秒间隔，也返回 200；客户端累计值为一天 2880 分钟。每条最多 1440 分钟的校验没有限制同日总量、重叠时间、日期或与真实计时的对应关系。

修复：若该指标用于评价，应由服务器签发计时会话并核算时间、排除重叠和重放；若保留离线自报，则明确标记为自报时长，不当作已验证的真实投入。

### 7. 普通账号可触发全量备份放大，耗尽磁盘

位置：`qiwu7_server.py:66–67`、`:282–290`。

同步写入没有账号速率限制、总状态大小配额和备份容量硬限制。每次实际变化都备份完整旧状态；单条字符串可达 50 万字符，请求最大 16 MiB。

已复现（仅临时目录，未做压力测试）：普通学生提交约 499 KB 的本人反馈，再提交两条很小反馈；3 次有效写入带来约 1,005,753 字节的新备份。随着总状态增长，每条小写入都能复制越来越大的全班数据。没有业务对象数量和存储总量约束时，磁盘增长没有应用侧上限。

修复：缩小各字段长度，限制单人每日提交量和写入频率；对当前状态、备份和审计日志分别设置容量监控与配额；采用增量审计及周期快照，在保留事故证据的前提下归档备份。磁盘不足应进入安全只读模式。

## 其他需加固但未作攻击验证的点

- 请求正文在认证之前读取，连接没有显式读取超时，ThreadingHTTPServer 缺少应用级连接数限制；应由反向代理限制连接、正文和超时。本次未进行慢连接或资源耗尽攻击。
- 登录和改密在全局 LOCK 内执行 PBKDF2；耗时认证可能阻塞同步和会话校验。应分离认证计算与状态锁，并对并发做限制。本次没有测量生产可用性影响。
- 退出后只撤销服务器 Cookie，未清理账号命名空间下的 localStorage 全量缓存。共享浏览器仍可能留下私密数据；需与读取视图修复一起处理。
- 临时密码生成脚本使用六位数字；虽然有首次改密和失败限流，仍应改为更长随机临时凭据并设置有效期。

## 验证与修复顺序

现有验证：`python3 -m unittest discover -s tests -p 'test_*.py' -v` 的 7 项测试通过；`node tests/test_sync.cjs` 的 3 项检查通过。它们覆盖部分认证、权限和同步行为，但未覆盖上述读取过滤、classroom 字段权限、畸形记录、业务重放和容量问题。

新增审计复现：`python3 security-audit/2026-10-28/reproduce.py` 确认 6 组本地问题，明文入口另经线上只读检查确认。

建议先限制公用一体机的写权限、过滤学生读取数据并启用 HTTPS；再补齐输入验证、业务幂等、学习计时和容量防护。修复应增加针对上述边界的回归测试，并在部署后单独验证。**本次交付为检查报告与隔离复现材料，没有修复、提交或部署业务代码。**
